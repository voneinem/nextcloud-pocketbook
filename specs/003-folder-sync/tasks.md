# Tasks: Folder Synchronization

**Input**: Design documents from `/specs/003-folder-sync/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md),
[contracts/sync-rules.md](contracts/sync-rules.md), [contracts/core-interfaces.md](contracts/core-interfaces.md),
[contracts/bridge-qml.md](contracts/bridge-qml.md), [quickstart.md](quickstart.md)

**Tests**: REQUIRED. The constitution makes Test-First non-negotiable (Principle I): every implementation task is preceded by
test tasks, and each story has a "red" task that records the new tests failing for the right reason before any implementation
task of that story starts. Tests that use the fake Nextcloud define `PBC_FAKE_SERVER_TEST` (`scripts/check-fake-markers.sh`).
Hand-written server answers carry the `.unverified` suffix (Principle IX).

**Organization**: Tasks are grouped by user story (US1-US9 of the spec) so each story can be implemented, tested and stopped
independently. Priorities: US1, US2, US3, US5, US8 are P1; US4, US6, US7, US9 are P2. **Phase order differs from story
numbers on purpose:** US3 (the reviewed download sync in the core) comes before US2 (the review screens and rules around the
plan) because the review needs a planner and a runner to review; US5 (triggers) and US8 (proof of repeatability) follow; the
P2 stories then extend the planner's decision table row by row.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1-US9, only in the user-story phases
- Paths are relative to the repository root. `core/include/pbc/X.h` and `core/src/X.cpp` come as a pair; every new
  `core/src/*.cpp` is added to `PBC_CORE_SOURCES` in `core/CMakeLists.txt` in the same task, every new bridge file to
  `bridge/CMakeLists.txt` (`PBC_BRIDGE_SOURCES`, `PBC_BRIDGE_HEADERS`, `PBC_BRIDGE_MOC_HEADERS`), every new bridge test to the
  `foreach` lists in `tests/CMakeLists.txt`, every new QML page to `qml/qml.qrc`. `tests/unit/test_*.cpp` and
  `tests/integration/test_*.cpp` are picked up by the glob.
- Every task that touches a user-visible text also adds the German entry to `qml/strings_de.tsv`
  (`scripts/extract-strings.py --check` must stay green).
- FR-/SC- numbers refer to [spec.md](spec.md); R- numbers to [research.md](research.md); "table row N" to the decision table in
  [contracts/sync-rules.md](contracts/sync-rules.md).
- No task adds a TLS bypass, a plaintext fallback, `Depth: infinity`, a new request kind, a write verb in a `sync_*` file, a
  timer outside the one allowed `QTimer`, polling, a retry timer, or a log field with server data or names (rules N1-N7
  enforce this mechanically).
- Unverified items stay unverified: no task marks a server or device behavior as verified; only the checklists do, with a date,
  after a real run.
