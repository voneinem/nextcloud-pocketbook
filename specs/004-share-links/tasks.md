# Tasks: Share Links

**Input**: Design documents from `/specs/004-share-links/`

**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md),
[contracts/share-requests.md](contracts/share-requests.md), [contracts/core-interfaces.md](contracts/core-interfaces.md),
[contracts/bridge-qml.md](contracts/bridge-qml.md), [quickstart.md](quickstart.md)

**Tests**: REQUIRED. The constitution makes Test-First non-negotiable (Principle I): every implementation task is preceded by
test tasks, and each story has a "red" task that records the new tests failing for the right reason before any implementation
task of that story starts. Tests that use the fake Nextcloud define `PBC_FAKE_SERVER_TEST` (`scripts/check-fake-markers.sh`).
Hand-written server answers carry the `.unverified` suffix (Principle IX).

**Organization**: Tasks are grouped by user story (US1-US7 of the spec) so each story can be implemented, tested and stopped
independently. Priorities: US1, US2, US3, US7 are P1; US4, US5, US6 are P2. **Phase order differs from story numbers on
purpose:** US7 (privacy) comes first because it defines the secret handling and the test harness every other story is written
inside; US2 (seeing the shares) comes before US1 (creating) because the Share screen is where Create lives; US3 (showing the
link) follows creation; the P2 stories then extend the link page.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1-US7, only in the user-story phases
- Paths are relative to the repository root. `core/include/pbc/X.h` and `core/src/X.cpp` come as a pair; every new
  `core/src/*.cpp` is added to `PBC_CORE_SOURCES` in `core/CMakeLists.txt` in the same task, every new bridge file to
  `bridge/CMakeLists.txt` (`PBC_BRIDGE_SOURCES`, `PBC_BRIDGE_HEADERS`, `PBC_BRIDGE_MOC_HEADERS`), every new bridge test to the
  `foreach` lists in `tests/CMakeLists.txt`, every new QML page and icon to `qml/qml.qrc`, every new walk to the `ui_walk` list in
  `app/CMakeLists.txt`. `tests/unit/test_*.cpp` and `tests/integration/test_*.cpp` are picked up by the glob.
- Every task that touches a user-visible text also adds the German entry to `qml/strings_de.tsv`
  (`scripts/extract-strings.py --check` must stay green).
- A log code is added to `core/src/log_codes.h` by the task that first logs it (`test_log` fails on unused codes).
- FR-/SC- numbers refer to [spec.md](spec.md); R- numbers to [research.md](research.md).
- No task adds a TLS bypass, a plaintext fallback, a write verb outside `core/src/share_api.cpp`, a timer, polling, a retry, a
  queue or a stored copy of a share, a log field with a link, token, password, address or name, or anything that opens a link
  (rules N1-N9 enforce this mechanically).
- Unverified items stay unverified: no task marks a server or device behavior as verified; only the checklists do, with a date,
  after a real run.

## Phase 3: User Story 7 - Links and passwords stay private (Priority: P1)

**Purpose**: the parts of the privacy promise that do not depend on a flow: the bridge's secret handling and `clearSecrets()`, the password field that cannot offer Copy, the link display that cannot be tapped, and the harness of `test_share_privacy` that every later story extends. Built early so every other story is written inside it.

**Goal**: a link or password is a secret with a defined lifetime; nothing the app writes or logs can hold one, and nothing the app does can open one.


**Independent Test**: with the bridge skeleton and the harness, inject a detail with a known link and a typed password, call `clearSecrets()`, and verify that the properties, the held detail and the clipboard-if-equal are cleared, that the log capture, the data folder and the database dump contain neither, and that the password field offers no Copy.
